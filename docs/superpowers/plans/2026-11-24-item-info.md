# Item Info Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** In the story, clicking a gear row's name in the Market or Lab, or a small `?` beside an item button on the equipment screen, opens a card with that item's live numbers, its price status and one line on what it is good for.

**Architecture:** A pure `itemCard(ref, world)` reads the config tables and the story's gear rules. The base-info card style is reused for a new `drawItemCard`. Hit testing gains a `name` hit on Market and Lab gear rows and a separate `equipmentInfoHit` for the `?` buttons (so the existing `EquipmentHit` kinds and their switches are untouched). `App` holds the open item and closes it like the soldier card.

**Tech Stack:** TypeScript strict, Canvas 2D (480x400 menu space), Vitest. Run: `npm test`, `npm run typecheck`, `npm run build`.

**Spec:** `docs/superpowers/specs/2026-11-24-laser-tribute-item-info-design.md`

## Global Constraints

- No rule, price or number changes; Tutorial and Campaign (including their equipment screens, which get no `?` buttons) are untouched. Opening or closing a card changes no state and writes no save.
- Every number comes from `WEAPONS`, `THROWABLES`, `GADGETS`, `ATTACHMENTS` and the story gear rules (`storyGearRules`, `unlocked`, the `*Price` functions in `src/core/loadout.ts`); nothing typed into the card except the labels and the `goodFor` lines (which contain no numbers).
- Card text: only supported characters, labels at most 10 characters, values at most 22, at most 12 rows, `goodFor` wrapped to at most 3 rows; nothing outside 0..480.
- The existing `EquipmentHit` kinds, `equipmentHit`, `applyEquipmentHit`, `blockReasonFor` and their tests are not changed. A `?` button must not overlap any existing equipment control (including the right-hand net-cost text at x=432 on the weapon row) and must sit inside 480x400.
- The `name` hit on Market and Lab rows reuses `NAME_W = 120`. Modal handling follows the base-info card: any click, BACK or Escape closes; opening locks input briefly; Escape ignores key repeat; leaving the screen closes it.

## Review Focus

- Every row of every item card equals the config table value (damage, range, AP costs, accuracies, magazine, falloff default 0.5, burst, sight, close penalty, blast size from the radius, effect wording, gadget and scope numbers) (Task 1).
- The price status is right for a researched item, an unresearched one (premium price as the equipment screen charges it), a starting item (pistol, rifle, frag, medkit) and a null world (Task 1).
- Market and Lab: only gear rows give a `name` hit; Lab upgrade rows, every other panel and the rest of a row do not; the Lab's second page maps rows to the right node (Tasks 2, 3).
- The `?` buttons never overlap or steal a tap from an existing equipment button, appear only in the story, and open the card of the item currently in that soldier's kit (Tasks 2, 3).
- Modal safety: click and Escape close it, Escape closes before leaving the equipment screen, no world or save change, a double-click does not close it (Task 3).

### Task 1: The item data

**Files:**
- Create: `src/core/world/iteminfo.ts`
- Test: `tests/iteminfo.test.ts`

**Interfaces:**
- Consumes: `WEAPONS`, `THROWABLES`, `GADGETS`, `ATTACHMENTS` from `../config`; `unlocked`, `type GearKind` from `../gear`; `weaponPrice`, `throwablePrice`, `gadgetPrice`, `attachmentPrice` from `../loadout`; `NODES`, `storyGearRules` from `./base`; `World` from `./world`; id types from `../types`.
- Produces:
  ```ts
  export type ItemRef =
    | { kind: 'weapon'; id: WeaponId } | { kind: 'throwable'; id: ThrowableId }
    | { kind: 'gadget'; id: GadgetId } | { kind: 'scope' };
  export interface ItemCard { title: string; rows: [label: string, value: string][]; goodFor: string }
  export function itemCard(ref: ItemRef, w: World | null): ItemCard;
  export function itemOfNode(nodeId: string): ItemRef | null;
  export const ALL_ITEMS: readonly ItemRef[];   // the 13 items: 5 weapons, 4 throwables, 3 gadgets, the scope, in that order
  ```

Rows, in this order and wording (percentages are `Math.round(x * 100)` followed by `%`):
- **weapon:** `DAMAGE` (`N`, or `NxB` for a burst), `RANGE`, `SNAP AP`, `AIM AP`, `SNAP ACC`, `AIM ACC`, `MAGAZINE`, `FALLOFF` (`w.falloff ?? 0.5`), then `SIGHT` only when `w.sight` is defined, `CLOSE` only when `w.closePenalty` (`x{multiplier} WITHIN {within}`), then `PRICE`.
- **throwable:** `AP`, `RANGE`, `BLAST` (`{2r+1}x{2r+1}`), `EFFECT` (frag `{damage} DMG`; smoke `SMOKE {turns} TURNS`; flash `STUN {apPenalty} AP`; incendiary `{damage} DMG + FIRE {turns} TURNS`), `PRICE`.
- **gadget:** medkit `HEAL`, `AP`; armour `DAMAGE` (`-30%` from `reductionPct`); scanner `AP`, `RADIUS`; then `PRICE`.
- **scope:** `ACCURACY` (`+10%`), `CRIT` (`+10%`), `PRICE`.
- **PRICE** is the base price as a number. When `w` is not null, a final `STATUS` row: `OWNED` when `unlocked(storyGearRules(w.research.done), gearKind, id)` (`gearKind` is `weapon`, `throwable`, `gadget` or `attachment` for the scope), else `PREMIUM {n} CR` where `n` is the same price the equipment screen charges under those rules (`weaponPrice(id, rules)`, `throwablePrice({ throwable: id }, rules)`, `gadgetPrice(id, rules)`, `attachmentPrice('scope', rules)`).
- `title` is the item's `name` uppercased (`SCOPE` for the scope).

`goodFor` text (no numbers; write exactly these):
pistol "A cheap backup: light, quick to fire, short reach." / rifle "The all-rounder: good reach and accuracy at a fair price." / shotgun "Hits hardest up close, and falls off fast with distance." / smg "Fires a burst: many small hits, best at medium range." / sniper "Kills from far away; weak when the target is close." / frag "Blast damage, and it breaks doors." / smoke "Blocks sight for a few turns: cover to cross open ground." / flash "Drains the action points of everyone it catches." / incendiary "Sets the ground on fire for a few turns, burning whoever stays." / medkit "Heals a soldier in the field." / armour "Cuts the damage the soldier takes." / scanner "Shows enemies near a spot, even through walls." / scope "More accuracy and crit chance for the shooter."

`itemOfNode(id)`: the item the research node gives (`gives.weapon`, `gives.throwable`, `gives.gadget`, `gives.attachment` as the scope), else `null` (including an unknown id).

### Task 3: Wire it into the app, and look at it

**Files:**
- Modify: `src/app.ts`
- Test: `tests/iteminfoapp.test.ts`

**Interfaces:**
- Consumes: `itemCard` (Task 1); `drawItemCard`, `panelItem`, `equipmentInfoHit`, `EquipmentView.infoButtons` (Task 2).
- Produces: `App` state `cardItem: ItemRef | null`, closed by the same `closeInfo()` as the soldier card.

Behaviour: in the `panel` click handler a `name` hit on a market or lab row (`panelItem(this.panelId, hit.index, this.panelPage)` not null) sets `panelSelected = hit.index` and `cardItem`, locks input and plays a click; the existing soldier `name` handling stays for barracks and training. In the `equipment` click handler (story only, `this.story && this.pendingSpec`): first, if an item card is open any click closes it and returns; then `equipmentInfoHit(mp.x, mp.y, this.loadout, slop)` (slop 3 for touch) not null sets `cardItem`, locks and returns before the normal button handling. `equipmentView()` sets `infoButtons: true` for a story fight. Escape on the equipment screen closes an open card first (ignoring repeat) and only then goes back to the squad step. `closeInfo()` also clears `cardItem`; `toTitle`, `backToSquad`, `openPanel`, `backToBase`, `backToPlanet` and `confirmSquad` clear it. The `panel` and `equipment` draw code draws `drawItemCard(ctx, itemCard(cardItem, this.story))` over the screen when `cardItem` is set.
